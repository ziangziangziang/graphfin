# GraphFin 首页 3D 主视觉 — 设计问题清单（求建议）

## 1. 项目背景

GraphFin 是一个「原生时序图数据库」，产品定位是一句话：

> **Relationships and observations, together.**（关系与观测，合为一体）

首页首屏（hero）右侧有一个 3D 主视觉：一段六边形碳晶格（ graphene 风格）沿品牌字母 **G** 的轮廓扫掠而成，携带一圈流走的金色信号脉冲。最近的版本做成「破框」效果：晶格会画出一个金色装饰边框，构成裸眼 3D 的出框感。

- 页面基调：深色（近黑 `#101315`）、克制、偏工程感，不是炫技型站点
- 字体/排版/配色/文案都已定稿，**只有这个 3D 物体需要设计判断**
- 首屏左侧是标题 + 描述 + 两个按钮，3D 物体占 viewport 宽度约 44%

## 2. 这个物体现在是什么

不是导入的模型，**是一个参数方程的像**：在 (u, v) 晶格上求值

- `u`：沿 G 中心线（首尾做 Chaikin 圆角）
- `v`：跨晶格宽度
- 深度 = 一个超线性 ramp，让两端向镜头冲刺；配合雾和两端淡出模拟景深
- 信号：单个脉冲沿晶格上的一条真实边路径行走
- 渲染：两个 InstancedMesh（球=节点、圆柱=连杆）+ 一个点云光晕 + 桌面端 bloom 和浅景深后处理

**关键限制：移动端（≤760px）完全关闭后处理**（无 bloom、无景深）。所以任何依赖光晕/虚化的“读法”，在手机上都会失效。

## 3. 真正的问题（不是“不够好看”，是这四条）

**(1) 遮挡关系曾经出错 —— 已修**
画面最左侧，内层骨架和外圈轨迹交叉处，结构深度按 `u` 分配导致内层被错误地画在外圈前面。已改为局部深度修正 + 局部层距加宽 + 球体局部缩小，并把该不等式写成了单元测试。同时删除了一个画布后方的模糊接触阴影——它透过透明画布看起来像物体上被挖了一个黑洞。

**(2) 景深曾经“前景糊到背景上”**
原来的景深是「按中心像素模糊、不看邻居深度」，导致远处模糊像素被平均进锐利前景像素，看起来像不可能的硬切。已改为 depth-aware 采样（只允许前景向背景扩散，禁止背景覆盖前景）。

**(3) 结尾在“溶解”，不像一个真实物体**
G 的两端用透明度淡出。在真实照片里这读作「物体损坏 / 建模没封口」，而不是「景深」。这是目前最刺眼的一点。

**(4) 语义几乎为零**
蜂窝＝图，这层语义成立。但时间只是「一个亮点在动」，没有周期、没有相位、没有「现在在哪」。而且这个亮点在闭合环上**没有参照系**——观者无法判断哪端是现在，这正是它看起来像「红绿灯跑马灯」而不是「时序」的原因。

## 4. 已经试过的方向

| 方案 | 做法 | 结论 |
|---|---|---|
| V1 闭合 G 环 | 首尾用横档闭合，去掉淡出 | 可行，最便宜；一圈＝一个周期 |
| V2 相位锁定 G 环 | 在平行移动标架上让截面每圈扭转 k=1 | 语义最强：周期变成几何量；尾部回折处标架易打旋 |
| V3 组合（外扭转壳 + 同轴内核） | 壳负责周期，中心金环负责「关系/观测的合取」 | **目前最强**，两个通道互不干扰 |
| V4 同轴内核 | 闭合壳 + 中心小金环 | 视觉最强，深度遮挡最可信 |
| 时间层栈（5 层轮廓 + 层间连杆） | 每层＝一个快照，深度＝时间轴 | **已否决并归档**：语义最直接，但 5 层叠加把轮廓打乱、连杆读作网格，整体散架 |

## 5. 硬约束（不能违反）

- 性能：移动端目标 24fps，实例数不能按层数线性爆炸
- 只能继续用「球 + 连杆」两类 instanced 图元 + 点云，最多再加一组
- 单条循环接缝（周期 u 参数），不能出现重复节点、断裂、硬切边
- 页面不能出现横向滚动条
- 必须像**真实相机拍的**：短焦、轻微强化透视、浅景深；虚化与遮挡必须自洽
- 降级路径：无 WebGL / 上下文丢失 / 用户开启减少动效时，必须有静态图兜底
- 桌面端要跑深度纹理景深 + bloom，**移动端没有任何后处理**

## 6. 想要你帮忙回答的问题

1. **「封口」应该怎么做才不像补丁？** 现在用一段横档把 G 的内端和头部连起来。横档太细像修补，太粗像畸形。参考物是什么（唱片刻线？缝合线？建筑梁？）？有没有更优雅的拓扑做法（比如让内端自然回卷进外圈）？
2. **闭合环上「现在在哪」应该怎么表达？** 试过对极双脉冲定义周期。是否应该在环上加刻度/相位刻痕？还是让「最近」通过景深+遮挡自然表达就够了，不要任何刻度？
3. **中心的内核（金环）应该多大、多亮？** 现在直径约占 G 内径一半、常亮。它是「观测」——但它会不会被误读成「靶心 / 加载中 / 眼睛」？要不要改成非同心（偏心）来更像两个数据域并置？
4. **扭转 k=1 的可读性够吗？** 它提供了明暗梯度，但会不会在小屏（~300px）变成脏噪点？是否该做成 k=0.5（半圈扭转）更干净？
5. **材质与光**：现在是低粗糙度金属 + 暖色主光 + 冷色轮廓光。真实感缺口在哪——环境反射太弱？缺少接触阴影？高光形状不像真实材质？（我们已考虑把景深 bokeh 从圆形改成六边形，呼应蜂窝主题，想听你意见值不值得。）
6. **「破框」和「真实感」是冲突的吗？** 物体画出装饰边框是强视觉手法，但它偏「海报/广告」，偏不「产品摄影」。如果要更像真实镜头，是保留破框、还是让物体老老实实待在画框内只靠景深出层次？
7. **如果只能改一处来提升「可信度」，你会改哪里？**

## 8. 说明

- 我们不是想要「更炫」，而是想要**看起来像一个真的被拍下来的物体，同时把「关系 + 时序」这层意思放进结构里而不是文案里**。
- 现有 3D 代码全在 `site/src/scene/`，几何是纯函数，改形状不需要美术资产。如果你给出方向，我们可以直接改参数实现；如果你想自己试，几何改动很小（主要是 `positionOnSpiral` 的几行）。
